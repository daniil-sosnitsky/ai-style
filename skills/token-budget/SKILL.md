# token-budget

Система из четырёх частей: **измерить → разгрузить → применить правила →
проверить.** Без последней части это набор советов: без замера до и после
экономию не отличить от спокойной недели.

## Главное, против интуиции

У модели нет памяти между шагами: чтобы ответить, ей заново подают весь
разговор. Поэтому расход — это **не то, что агент пишет, а то, что он
перечитывает**.

Замер реальной работы (154 сессии, 6014 обращений, 30 дней):

| Статья | Доля бюджета |
|---|---|
| Перечитывание контекста | **96,8%** |
| Запись контекста в кэш | 2,6% |
| Ответы модели | **0,6%** |

Отсюда: просить агента отвечать короче бессмысленно — это полпроцента счёта.
Экономия живёт в размере контекста, длине сессии и в том, кто его читает.

## Три диагностики

```bash
python scripts/token_report.py              # куда уходит: четыре статьи, срезы
python scripts/token_report.py --startup    # цена входа в сессию
python scripts/token_report.py --growth     # как дорожает шаг с длиной сессии
```

Что смотреть в каждой:

**Основной отчёт.** Отношение чтений к записям кэша — порог окупаемости 2 при
пятиминутном TTL и 3 при часовом. Ниже порога кэш рвётся: платится премия за
запись без скидки за чтение. Строка «Кто тратит» показывает долю субагентов:
если механика им не отдана, а доля заметная — их зовут не по делу.

**Цена входа.** Системная инструкция, описания всех инструментов и файлы правил.
Платится в каждой сессии и перечитывается на каждом шаге. Главный источник
лишнего веса — подключённые про запас MCP-серверы: каждый приносит описание
каждого своего инструмента.

**Рост сессии.** Цена шага растёт вместе с длиной разговора, потому что каждый
шаг перечитывает накопленное. В замере шаг в длинной сессии дороже шага в
короткой в 3,3 раза. Если видно резкий рост — там и надо было дробить работу.

## Разгрузка: четыре субагента

Лежат в `agents/`, ставятся установщиком в `~/.claude/agents`.

| Агент | Модель | Берёт на себя |
|---|---|---|
| `scout` | Haiku | Поиск по файлам, сбор фактов, разбор структуры |
| `log-digger` | Haiku | Логи, трассировки, выводы сборки и тестов |
| `routine` | Sonnet | Однотипные правки по готовой спецификации |
| `reviewer` | Sonnet | Чтение изменений и поиск проблем, без правок |

Смысл субагента — изоляция контекста, а не параллельность: шумная работа идёт в
его окне, назад приходит итог. **Критично:** если в настройке агента не указана
модель, он наследует родительскую и экономии нет. В этих четырёх указана явно.

Не звать субагента ради одного файла — он поднимает окно с нуля. Не разворачивать
группу агентов без причины: каждый грузит контекст заново и кэш не делит.

**Не отдавать дешёвой модели:** доступы, ключи, безопасность, выбор архитектуры.
Переделка дороже экономии.

## Правила

`rules/CLAUDE.snippet.md` — переносится в `CLAUDE.md` целиком. Четыре группы:
работа с контекстом, длина сессии, кэш, выбор модели.

Коротко самое весомое:

- файл читать фрагментами, а не целиком;
- большие выводы команд — в файл, не в разговор;
- картинки — через субагента;
- одна сессия — одна задача;
- инструкции править между задачами, а не внутри: правка начала контекста
  обнуляет кэш всей сессии;
- инструменты не подключать про запас — они в начале контекста и оплачиваются
  на каждом шаге.

## Механика кэша

| Что | Цена | Окупаемость |
|---|---|---|
| Чтение из кэша | 0,1× от входа | — |
| Запись, TTL 5 минут | 1,25× | со 2-го запроса |
| Запись, TTL 1 час | 2× | с 3-го запроса |
| Пакетная обработка | −50% на вход и выход | ответ до 24 ч |

**Срок жизни кэша считается от начала запроса, а не от конца.** Генерация
съедает TTL: ответ, писавшийся четыре минуты, оставляет минуту до истечения
пятиминутной записи. В агентской работе с долгими шагами это главная причина
рваного кэша — отсюда часовой TTL для длинных сессий. Любое чтение бесплатно
продлевает срок жизни записи.

## Контроль

```bash
python scripts/token_report.py --days 14 --save baseline.json
# ...изменения...
python scripts/token_report.py --days 14 --compare baseline.json
```

Сравнивается **удельный расход** — цена одного шага. Абсолютные цифры недель
несравнимы: в неделю с большими задачами токенов всегда больше.

- разница в пределах ±5% — шум, не результат;
- упало перечитывание на шаг — контекст стал меньше, это главный признак;
- выросла запись относительно чтения — кэш стал рваться чаще;
- доля субагентов выросла, а удельный расход упал — механика уехала с дорогой
  модели, так и задумано.

Снимок снимается **до** изменений.

## Чего система не делает

- **Не ставит хуки.** Существующие решения либо правят исполняемый файл Claude
  Code и ломаются при обновлении, либо блокируют команды по совпадению текста и
  дают ложные срабатывания. На чужой машине это недопустимо.
- **Не считает счёт.** Токены — факт, деньги — оценка по тарифу из
  `pricing.json`. На подписке это «во сколько обошлось бы по API».
- **Не экономит за счёт качества** и не трогает лимиты тарифа.
