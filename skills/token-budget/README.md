# token-budget

Система, которая показывает, куда у тебя уходят токены в Claude Code, и
удерживает расход дальше — без твоего участия.

Ставится одной командой, работает без интернета и без API-ключей.

---

## Сначала — почему агент вообще дорожает

Представь, что собеседник перед каждой своей фразой **перечитывает всю вашу
переписку с самого начала**. Не помнит её — а именно перечитывает, заново, от
первого сообщения.

Примерно так и работает ИИ-агент. У модели нет памяти между шагами: чтобы
ответить на твой десятый вопрос, ей заново подают весь разговор — все
предыдущие вопросы, все прочитанные файлы, все выводы команд. И ты платишь за
это чтение каждый раз.

Отсюда три следствия, которые противоречат интуиции:

**1. Платишь не за ответы агента, а за чтение.**
Замер реальной работы за месяц — 154 сессии, 6014 обращений к модели:

```
Перечитывание разговора     96,8%  ████████████████████████████████████████████████
Запись разговора в память    2,6%  #
Ответы агента                0,6%
```

На один шаг приходится около 160 тысяч токенов перечитанного и 800 токенов
ответа. Поэтому популярный совет «проси отвечать покороче» воюет за полпроцента
счёта.

**2. Чем длиннее разговор, тем дороже каждый следующий шаг.**

| Длина сессии | Цена одного шага | Вся сессия |
|---|---|---|
| 1–20 шагов | 57 тысяч | 0,6 млн |
| 51–100 | 164 тысячи | 11,9 млн |
| больше 200 | 199 тысяч | 54,7 млн |

Сессия на 276 шагов длиннее сессии на 11 шагов в 25 раз — а стоит в 90 раз
дороже. Это не потому, что задачи были сложнее: тот же эффект виден **внутри
одной сессии**, где последняя четверть стоит в полтора раза дороже первой.

**3. Ты платишь ещё до того, как сказал первое слово.**
В начало каждого разговора кладутся системная инструкция, описания всех
подключённых инструментов и файлы правил проекта. В замере это 19 тысяч токенов
в типичной сессии и до 63 тысяч в тяжёлой. Каждый подключённый MCP-сервер
добавляет сюда описание каждого своего инструмента — и ты платишь за них, даже
если ни разу их не вызвал.

---

## Что делает эта система

Она отвечает на три вопроса и даёт инструменты, чтобы ответы менялись в лучшую
сторону.

| Вопрос | Команда | Что увидишь |
|---|---|---|
| Куда уходят деньги? | `token_report.py` | Четыре статьи расхода, разбивка по моделям, дням и проектам |
| Сколько стоит вход в сессию? | `token_report.py --startup` | Вес инструментов и инструкций, которые грузятся до первого слова |
| Когда сессия стала дорогой? | `token_report.py --growth` | Как росла цена шага и где пора было остановиться |

Плюс две части, которые работают дальше сами:

- **Четыре готовых субагента** — забирают механическую работу на дешёвые модели;
- **Готовые правила** для инструкции агента — он применяет их без напоминаний.

И последнее: **проверка, что экономия настоящая**, а не показалось.

## Установка

```bash
git clone <адрес репозитория>
cd token-budget

./install.sh          # macOS, Linux
.\install.ps1         # Windows
```

Установщик кладёт четырёх субагентов в `~/.claude/agents` и показывает, что
делать дальше. **Он не трогает твои настройки и твой CLAUDE.md** — правила ты
вставишь сам, одним копированием. Если агент с таким именем у тебя уже есть,
установщик его не перезапишет.

Нужен Python 3.9 или новее — без внешних библиотек, всё на стандартной.

## Из чего состоит и зачем каждая часть

### 1. Отчёты — `scripts/token_report.py`

Claude Code и так записывает каждое обращение к модели в файл у тебя на диске.
Скрипт эти записи разбирает. Никуда ничего не отправляет: читает то, что уже
лежит.

```bash
python scripts/token_report.py                 # за последний месяц
python scripts/token_report.py --days 7        # за неделю
python scripts/token_report.py --by day        # по дням
python scripts/token_report.py --by project    # по проектам
python scripts/token_report.py --startup       # цена входа в сессию
python scripts/token_report.py --growth        # как дорожала сессия
```

Хочешь видеть деньги — скопируй `scripts/pricing.example.json` в
`pricing.json`, сверь цифры со своим тарифом и добавь `--pricing
scripts/pricing.json`. Цены специально лежат отдельно от кода: тарифы меняются
чаще, чем обновляются скрипты.

### 2. Субагенты — `agents/`

Субагент — это помощник с **собственной** памятью разговора. Он делает шумную
работу у себя и возвращает в твою сессию только короткий итог. Двадцать
прочитанных файлов остаются у него, к тебе приходят три строки.

| Агент | Модель | Для чего | Почему дешёвая модель справится |
|---|---|---|---|
| `scout` | Haiku | Найти, где что лежит, собрать факты | Поиск — это аккуратность, а не суждение |
| `log-digger` | Haiku | Разобрать лог, понять, почему упало | Причина обычно лежит на поверхности вывода |
| `routine` | Sonnet | Однотипные правки по готовой спецификации | Решение уже принято, осталось применить |
| `reviewer` | Sonnet | Прочитать изменения и найти проблемы | Найти — не то же самое, что чинить |

⚠️ **Главная ошибка при переносе на дешёвые модели** — забыть указать модель в
настройке агента. Тогда он наследует модель родителя, и экономии нет вообще.
В этих четырёх модель прописана явно.

**Где дешёвая модель не нужна:** доступы, ключи, безопасность, выбор
архитектуры. Там ошибка стоит дороже сэкономленного, и агенты для этого
намеренно не сделаны.

### 3. Правила — `rules/CLAUDE.snippet.md`

Копируешь блок в свой `CLAUDE.md` — дальше агент держит их сам. Это правила про
чтение файлов кусками, про большие выводы команд, про длину сессии и про то,
когда звать субагента.

### 4. Проверка результата

Сравнивать «было 10 миллионов, стало 8» бесполезно: в неделю с тремя большими
задачами токенов всегда больше. Смотреть надо на **цену одного шага**.

```bash
python scripts/token_report.py --days 14 --save baseline.json
# ...вставил правила, поставил агентов, поработал неделю...
python scripts/token_report.py --days 14 --compare baseline.json
```

Разница меньше 5% — это шум, а не победа. Снимок снимается **до** изменений.

## Чего эта система не делает

**Не ставит хуки — и это сознательно.** Хук может автоматически вмешиваться в
работу агента, и звучит это заманчиво. Но когда я разобрал, что делают
существующие решения, оказалось: один из популярных проектов правит
исполняемый файл Claude Code и ломается при каждом его обновлении, а хуки,
блокирующие команды по совпадению текста, дают ложные срабатывания и подвешивают
чужую работу. На своей машине с этим можно жить. В продукте, который ставят
другие люди, — нет.

**Не показывает твой счёт.** Скрипт считает токены; деньги — оценка по тарифу,
который ты сам впишешь. На подписке с фиксированной платой это «во сколько
обошлось бы по API», а не списание.

**Не экономит за счёт качества.** Дешёвая модель на задаче, где нужно суждение,
даёт переделку, а переделка стоит дороже сэкономленного.

**Не трогает лимиты тарифа.** Это про расход, а не про квоты.

## Что ещё стоит посмотреть

Эти инструменты в систему не входят, но решают соседние задачи. Все три живые,
проверены по состоянию на 5 октября 2026 года.

| Инструмент | Что делает | Как поставить |
|---|---|---|
| [ccusage](https://github.com/ryoppippi/ccusage) | Самый популярный счётчик расхода: отчёты по дням, неделям и сессиям. 18,9 тыс. звёзд | `npx ccusage` |
| [ccstatusline](https://github.com/sirmalloc/ccstatusline) | Строка состояния с расходом и заполнением контекста прямо в терминале. 13,2 тыс. звёзд, MIT | `npx -y ccstatusline@latest` |
| [Claude Code Usage Monitor](https://github.com/Maciek-roboblog/Claude-Code-Usage-Monitor) | Живой дашборд с прогнозом, когда кончится лимит. 8,7 тыс. звёзд, MIT | `pip install claude-monitor` |

⚠️ Запуск через `npx -y ...@latest` всегда тянет свежую версию с чужого сервера
— это общий риск такого способа установки, не особенность конкретного проекта.

## Откуда взяты цифры

Все проценты и таблицы в этом файле — замеры одной реальной машины за месяц
работы (154 сессии, 6014 обращений к модели). Твои будут другими: для того
скрипты и приложены.

Множители кэша (чтение дешевле входа в 10 раз, запись дороже в 1,25–2 раза) и
скидка пакетной обработки взяты из документации Anthropic.
