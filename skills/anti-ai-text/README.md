# anti-ai-text — убрать из текста нейросетевой почерк

Текст написан с моделью, читается гладко, а в комментариях прилетает «это же
нейросеть писала». Проблема не в том, что модель пишет плохо. Она пишет
**узнаваемо**: одно и то же тире вместо любого знака, одинаковые абзацы,
«стоит отметить» через каждый экран и вывод, который ничего не добавляет.

Здесь лежит то, чем я снимаю эти следы со своих текстов: скрипт-проверка, разбор
следов по трём уровням и скилл для Claude Code, который гоняет это сам.

## Что внутри

| Файл | Что это |
|---|---|
| `scripts/check_text.py` | Проверка файла или папки. Показывает, что и в какой строке править |
| `rules/anti-ai-patterns.md` | Разбор следов: три уровня, примеры замен, как **не** чинить |
| `rules/phrase-stoplist.txt` | Шаблон личного стоп-листа: твои собственные повторы |
| `SKILL.md` | Инструкция для агента, если работаешь в Claude Code |

## Как попробовать за минуту

Python 3.9 или новее, больше ничего не нужно: ни ключей, ни интернета.

```bash
python scripts/check_text.py мой-текст.md
```

Вывод выглядит так:

```
мой-текст.md
  [блокер] строка 15: длинное тире (1 шт.) - замени на дефис, запятую, двоеточие или скобки
  [блокер] строка 23: эмодзи в тексте: 🚀
  [правка] весь текст: штампов 11 на 1165 знаков = 9.4 на 1000 (норма 1)
  [правка] строка 11: канцелярит: «является»
  [правка] строка 15: переименование предмета: «этот инструмент»
  [правка] строка 7: подзаголовок-пустышка: «Введение» - он маркирует место, а не говорит о смысле
  [правка] весь текст: абзацы одной длины: 6 абзацев, в среднем 179 знаков, разброс 0.14 (нужен > 0.35)

Итого блокеров: 2
```

**Блокер** это то, что правится однозначно. **Правка** это место, где нужно
решение автора: иногда «является» стоит ровно там, где надо.

## Ключи

| Ключ | Зачем |
|---|---|
| `--stoplist <файл>` | Подключить личный стоп-лист фраз |
| `--no-dash` | Разрешить длинное тире |
| `--social` | Пост для соцсети: тире и эмодзи там норма формата, а не след |
| `--quiet` | Только блокеры, без правок |

Код возврата `0` если блокеров нет, `1` если есть, так что проверку можно
повесить на git-хук или на CI.

## Что проверяется

**Уровень 1, блокеры.** Длинное тире, эмодзи в теле текста, кликбейт-словарь,
личный стоп-лист.

**Уровень 2, плотность штампов.** «Стоит отметить», «таким образом», «в
современном мире» не запрещены, но их норма не больше одного на 1000 знаков.
Скрипт считает плотность, а не факт наличия.

**Уровень 3, структура.** Самое интересное и самое невидимое при вычитке
глазами:

- **ровный ритм абзацев** — считается разброс длин. У живого текста он больше:
  короткий абзац, потом длинный, потом опять короткий;
- **подзаголовки-пустышки** — «Введение», «Основная часть», «Заключение»
  маркируют место, а не говорят о смысле;
- **поздняя ценность** — в первых 70 словах нет ни цифры, ни обращения к
  читателю, то есть текст пока разгоняется;
- **канцелярит и переименования** — «является», «данный», а также «этот
  инструмент» вместо второго упоминания предмета.

## Чего скрипт не умеет

Он не умеет главного: проверить, есть ли в тексте то, чего не было в источниках.
Поэтому после проверки он печатает четыре вопроса, на которые отвечает автор:

1. Есть ли в тексте мысль, которая не собирается из чужих статей?
2. Можно ли убрать первые два абзаца без потери смысла?
3. Структура похожа на маршрут мысли или на автоматический план?
4. Есть ли место, где сказано «вот тут я не уверен» или «это работает, но»?

Если на первый вопрос ответа нет, чистка формулировок не поможет. Текст без
собственного вклада читается как сгенерированный, даже когда в нём ни одного
маркера.

## Как поставить себе

### Как скилл для Claude Code

```powershell
.\install.ps1        # Windows
```

```bash
./install.sh         # Linux, macOS
```

Установщик копирует папку в `~/.claude/skills/anti-ai-text` и ничего больше не
трогает: твои `CLAUDE.md` и `settings.json` остаются как были. После перезапуска
Claude Code скилл подхватится сам и будет включаться на «почисти текст» и
«звучит как нейросеть».

### Просто как скрипт

Скачай папку, запускай `scripts/check_text.py` на своих файлах. Скилл и правила
при этом не нужны, но в `rules/anti-ai-patterns.md` лежат замены, которых скрипт
не подсказывает.

## Как это настроить под себя

Два места, которые стоит поправить под свой формат.

**Порог ритма.** `RHYTHM_CV_THRESHOLD = 0.35` в начале скрипта. Это разброс длин
абзацев, ниже которого текст считается слишком ровным. Прогони свои старые
тексты, которые тебе нравятся: если скрипт жалуется на них, порог нужно
опустить.

**Плотность штампов.** `CLICHE_PER_1000 = 1.0`. Для технической документации
норму можно поднять, для текста в соцсети опустить.

Цифры в примерах мои, с моего корпуса статей. Копировать их не надо, скрипт
посчитает твои.
