# topic-radar - система поиска тем для статей и постов

Скил для Claude Code, который отвечает на один вопрос: **о чём писать дальше и
почему именно об этом.**

Не генератор идей. Идею придумать легко - тяжело не повторить себя и не
перекосить канал в одну сторону. Это видно только когда смотришь на весь корпус
сразу, а не на одну тему.

## Что он делает

| Шаг | Что происходит |
|---|---|
| Карта написанного | каждая вышедшая статья разбирается на пару **объект + угол** - это ключ антидубля |
| Синхронизация банка тем | статусы идей сверяются с реальностью выпусков, без вопросов |
| Диагностика канала | баланс рубрик, завал неопубликованного, сгорающие темы |
| Спрос | пакетная частотность Яндекс Вордстата по 15-25 фразам разом |
| Свежесть | дайджест тематических Telegram-каналов + веб-поиск по нише |
| Скоринг | 8 критериев, 100 баллов, плюс четыре жёстких отсечки |
| Отчёт | очередь тем, отсортированная по баллу, с обоснованием каждой |

## Чем он отличается от «спроси у нейросети темы для блога»

Три вещи, которых у разового запроса нет в принципе.

**1. Он видит, что уже написано.** Две статьи с одинаковой парой объект+угол
делят между собой один и тот же поисковый запрос и обе проигрывают. Радар
отсекает такого кандидата, а не снижает ему балл.

**2. Он считает по своим цифрам, а не по общим советам.** Веса критериев
пересчитаны по корпусу из 34 статей и 280 тысяч показов. Четыре отсечки -
каждая подтверждена замером, а не вкусом. Например: статьи с аббревиатурой в
заголовке дают CTR вдвое ниже при тех же показах; темы «ИИ в [сфере]: как
повысить» дают дочитываемость 2%.

**3. Он знает, что ни одна тема не даёт всего сразу.** Массовый бренд или закон
собирают клики, но до конца статьи доходит каждый десятый. Личный эксперимент
дочитывают, но почти не открывают. Инструменты не дают ни охвата, ни дочитки,
зато дают подписки. Это три разные задачи, и планировать надо все три.

## Скоринг

| Критерий | Вес |
|---|:-:|
| Порог входа - поймёт человек вне темы | 25 |
| Массовость предмета - бренд, новость, деньги, закон | 18 |
| Личный опыт - автор это делал | 18 |
| Свежесть - привязка к инфоповоду | 12 |
| Поисковый спрос - цифры и тренд | 9 |
| Недобранная рубрика | 8 |
| Новизна угла | 5 |
| Лид-магнит - из темы выжимается файл | 5 |

⚠️ **Это не универсальная истина, а результат замера одного канала.** Логику
скоринга бери себе, цифры пересчитывай под свой корпус. Как считать и что на
чём проверено - в разделе «Что показали 34 статьи» в [`SKILL.md`](SKILL.md).

## Как поставить себе

1. Скопируй `SKILL.md` в `~/.claude/skills/topic-radar/SKILL.md`.
2. Заведи четыре файла канала - индекс вышедших статей, банк тем,
   позиционирование, профиль канала. Имена свои, важна роль; что именно скил из
   каждого берёт, расписано в разделе «Что нужно, чтобы поставить себе».
3. Для Фазы 3 поставь скрипт частотности: [`wordstat/`](../../wordstat/). Ключ
   API - через `.env`, в коде его нет. Без ключа скил не падает, а помечает блок
   спроса как «оценка без API».
4. Поправь веса и отсечки под свой канал. Чужие цифры без пересчёта - худшее,
   что можно сделать с этим скилом.

Дайджест Telegram-каналов (Фаза 4) - необязательный источник. Нет его - скил
работает, просто отмечает это в отчёте одной строкой.

## Чего он не делает

Не пишет текст и не публикует его. Не решает за автора, сколько статей писать:
показывает состояние канала и очередь, темп выбирает человек.
