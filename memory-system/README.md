# Система памяти для ИИ-агента

Нейросеть обнуляется каждый новый чат. Контекстное окно — рабочий стол одного
разговора: закрыл чат, стол убрали. Чтобы ИИ помнил тебя между сессиями, память
надо вынести наружу, в файлы.

Но свалка файлов памятью не становится. Ниже — структура, которая реально
работает у меня каждый день: **три отдела** с разными правилами и условным
чтением.

---

## Отдел 1. Кто я — профиль личности

Семь заметок: `identity`, `values`, `mission`, `spheres`, `strengths`,
`working-style`, `voice`.

Их не пишут за один присест. Честно ответить на «какие у тебя ценности» с чистого
листа невозможно, а по одному наводящему вопросу — вполне. Поэтому профиль
собирается интервью: скилл задаёт по вопросу за раз и сам сводит ответы в
структурированную заметку.

Профиль **не грузится целиком в каждый разговор**. К каждой заметке приписано
условие, когда её открывать:

| Ситуация | Что подтянуть |
|---|---|
| Планирую день, приоритизирую задачи | `working-style` + `strengths` |
| Решаю, куда двигаться в работе | `mission` + `identity` + `values` |
| Приуныл, сравниваю себя с другими | `strengths` + `identity` |
| Любой разговор вообще | `voice` |
| Речь про отдых, здоровье, отношения | `spheres` |

Без этих условий система разваливается на втором десятке файлов: в контекст лезет
всё сразу и полезное тонет.

## Отдел 2. Факты и опыт

Один файл — один факт. Шаблон: [`templates/fact.md`](templates/fact.md).

У каждого факта есть **тип**, и тип решает, как факт использовать:

| Тип | Что туда попадает |
|---|---|
| `user` | Кто такой пользователь: роль, уровень, предпочтения |
| `feedback` | Что он поправил в работе ИИ и **почему** именно так |
| `project` | Текущие задачи и ограничения, которых не видно в коде |
| `reference` | Внешние ресурсы: ссылки, дашборды, тикеты |

Плюс файл-индекс [`templates/MEMORY.example.md`](templates/MEMORY.example.md): на
каждый факт одна строка. Индекс подгружается в начале сессии, и модель сразу
видит, что у неё есть, не открывая всё подряд.

**Что НЕ писать в память** (главное правило, без него всё забивается мусором):

- то, что и так есть в проекте: структура кода, история коммитов, содержимое
  конфигов;
- то, что важно только для одного разговора.

## Отдел 3. Правила работы

Правила живут отдельно от фактов, в файлах `CLAUDE.md`, и у них три уровня:

```
~/.claude/CLAUDE.md      общие для всего: тон, запреты, стандарты кода
<проект>/CLAUDE.md       специфика проекта
<подпроект>/CLAUDE.md    специфика части проекта
```

Шаблон верхнего уровня: [`templates/CLAUDE.example.md`](templates/CLAUDE.example.md).

Нижний уровень перебивает верхний. Держать одно и то же правило на двух уровнях
нельзя: копии разъезжаются, и потом непонятно, какая настоящая.

---

## Две грабли, проверенные лично

**Мусор побеждает.** Соблазн записывать всё — главный убийца системы. Показательный
случай: разработчик инструмента памяти skillmem за одни сутки выпустил 11 релизов
подряд, когда сел проверять собственный продукт. Одна из находок — система
записывала текст ошибки `usage limit reached` как полезную заметку, и он затирал
нормальную выжимку по задаче.

**Память привязана к пути.** Она цепляется к конкретной папке, из которой запущен
агент. Открыл на уровень выше — стартуешь вслепую, без единой заметки, хотя все
файлы лежат рядом. Лечится файлом-заглушкой в родительской папке, который прямо
говорит агенту: «ты не там, перезапустись отсюда».

## Чем это обслуживается

Наполнять память руками — значит перестать её наполнять через неделю. У каждого
отдела есть скилл, который его ведёт:

| Скилл | Роль |
|---|---|
| `profile` | Интервью и синтез семи заметок профиля |
| `claude-md-writer` | Пишет и чистит файлы правил, следит за уровнями |
| `checkup` | Раз в пару дней ищет дубли, противоречия, устаревшие записи |
| `skill-creator` | Собирает новый скилл, когда появляется повторяющийся сценарий |

Скилл [`morning`](../skills/morning/) из этого репозитория — пример потребителя
памяти: он читает профиль и факты, чтобы спланировать день.
